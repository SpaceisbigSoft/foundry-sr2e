## Bugs found while writing

Found by reading the code; each has a check marked **Watch** that shows it live.

1. **A Stress failure's Crash Test gets an unintended +2 TN.** `applications/vdrive98.ts:339` puts `crashTest: { tn: 0, … }` on the drive card (no extra TN meant); the button handler clamps it with `safeInt(c.tn, 2, 30, 4)` (`applications/chat.ts:1537, 1539`), so `crashTestFor({ tn: 2 })` (`documents/index.ts:18715`) adds a "+2 a system failure" row. Scenario: a failed Driving Test whose Stress Test fails, then the Crash Test button (check 10).
2. **A player's chase turn loses its positioning successes.** `applications/vdrive98.ts:354`: on a non-GM client `afterPositioning` only returns the "count toward next turn's Driver Points once the GM runs the turn" line; nothing records the successes anywhere (the combat is GM-only and `rollScores` reads only the combat's `carry`), so the GM's next Maneuver Scores never include them. Scenario: the player's vehicle is the pursuer and its owner runs `chaseTurn` (check 17).
3. **A continuous-lock missile launch is recorded even when the attack is refused.** `applications/vrig98.ts:148` writes `vrig98Lock` on the firing vehicle from inside `planAttack` (`documents/index.ts:9242`); `#attackWith` calls `planAttack` first (`:9470`) and only then refuses an empty launcher (`:9471–9474`) or a failed quick-draw/action. Scenario: continuous lock with the launcher at 0 ammo → "out of ammo", yet the vehicle's Driving Tests get +2 for the turn (check 34).
4. **A copy of a MIJI card applies again.** `applyMiji` (`applications/vrig98.ts:446–469`) guards only the card itself (`vrig98Done`); a player can post a copy of their real MIJI card (same flags, same `rolls`) and every check passes again (author owns the intruder, interception, dice re-count), so the GM's Apply puts the boxes on twice. The access flow has a "first roll card for the request" guard; MIJI has none. Scenario: check 68(d).
5. **Double-click on "Light to the vehicle (GM)" can do 2 boxes.** `applications/vdrive98.ts:267–271`: the done flag is read before and written after the `gmMay` confirm, and `button.disabled` is set only after it, so two quick GM clicks on a player's card open two confirms; confirming both applies Light twice (check 73).
6. **Double-click on a rigger combat Resist with Control Pool left resists twice.** `applications/vsec98.ts:447–465`: the pool prompt opens before `button.disabled` and before the done flag; two clicks → two prompts → two resistance tests (check 73).
7. **The access roll's Apply (GM) has no in-flight guard.** `applications/vsec98.ts:436–439, 481–513`: no `button.disabled`, and `vsec98Applied` is written after the `gmMay` confirm: a double click opens two confirms and applies twice (two GM notes; a failed decryption calls `changeSite` twice) (check 73).
8. **"Only the first roll counts" can be beaten by deleting the first roll.** `firstRollFor` (`applications/vsec98.ts:470–474`) looks for the first roll card *still in the chat*; a player who can delete their own messages can roll again, delete the failed roll card, and have the GM apply the second (check 70, Record whether a player may delete their own card).
9. **The captain's chair button shows without a control rig.** `chairContext` (`applications/vrig98.ts:261–263`) needs only a remote control deck; `captainInitiative` (`rules/vrig98.ts:76`) also needs a VCR. A rigger with an RCD and no VCR can "sit" (the card says the rig's Initiative counts) but nothing changes (check 39).
10. **The optional ED rule's Signature shows on the scanner's public card.** The ED/ECD card is whispered to the GMs (`applications/vrig98.ts:120`, "the GM's secret"), but its `ed98` "Electronic deception: Signature +n" row (`:116`) goes on the scanner's own Sensor Test card for everyone (check 33).
11. **The link's encryption row reads only the drone's own encryption.** `linkFlux` (`applications/vrig98.ts:305`) uses `droneLinkOf(vehicle.system).encryption`; the link's encryption elsewhere is the better of the drone's and the rigger's deck's (`rules/dronelink.ts:56` `linkEncryption`). An encrypted deck with an unencrypted drone gets no −0.5 (check 41, P2 part).
12. **The rigger decking exception counts datajacks by name only.** `datajackCount` (`rules/vsec98.ts:161–163`) matches "datajack" in the name; the rest of the system knows a datajack by `kind: 'datajack'` or by name (`models/index.ts:266`). A second datajack named "ZZ Jack Port" (kind datajack) doesn't lift the penalty (check 58).
13. **Running "Maneuver Scores" twice in one Combat Turn drops the carried positioning successes.** `withScores` (`rules/vdrive98.ts:261–264`) empties `carry`; `rollScores` (`applications/vdrive98.ts:388–412`) has no once-per-turn guard, so a second press re-rolls everyone without last turn's successes (check 16).
14. **The install dialog names the wrong skill.** The vehicle sheet's Install dialog still labels each mechanic by the old vehicle B/R skills (`applications/sheets.ts:6953`), while `installModTest` now rolls Electronics B/R (sensors, ECM, ECCM, ECD) or Computer B/R (pilot) first (`documents/index.ts:19454`): the dialog says "(no B/R skill)" or "Car B/R …" for a test that rolls Electronics B/R (check 61).
