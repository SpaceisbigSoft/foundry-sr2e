Two tabs: **GM** (GM AI) and **PL** (ZZ Testplayer). Drive the UI with JavaScript in the page and read the DOM and documents; take the screenshots marked **[SHOT]**. After a click, an update or a new chat card, wait about 500 ms before reading (older cards are switched off 50 ms after a new card arrives). Every test document is named "ZZ …" (the NPC generator's actors in section M are the exception: they are found by id). A browser reload (F5) is enough after deploying: there are no new document types, only new schema fields (character `system.matrix.knownHosts`, `system.lifestyle.outright`, training entry `by`; vehicle `system.link`, `system.firmpoints`, `system.hardpoints`; sensor-lock entry `round` and `worldTime`; weapon `system.mountPoint`), and `system.metatype` and `system.lifestyle.level` lost their fixed choices. Each check: **steps** → *expected*. Write down anything that differs, plus the console errors seen during the check. "Forced click" means: set `b.disabled = false` on the dead button, then `b.click()`. "Record" means: the code's behaviour is not obviously right; write down what happens.

The changes are in section 3 of `docs/REVIEW-v0.69.md` (O22–O43). The switches are `RULES.NETRIG_V73` (`rules/config73/netrig.ts`, O22–O27), `RULES.DRONES_V73` (`rules/config73/drones.ts`, O28), `RULES.CHARACTERS_V73` (`rules/config73/characters.ts`, O29–O38) and `RULES.CROSSCUT_V73` (`rules/config73/crosscut.ts`, O39–O43), with 77 house-rule rows at the end of `HOUSE_RULES` (`settings.ts`). ## How to drive it

- **Cards.** `const last = (f = () => true) => game.messages.contents.filter(f).at(-1);` `const btns = (m, sel) => [...document.querySelectorAll(`[data-message-id="${m.id}"] ${sel}`)];`. A card normally shows twice (chat log and pop-up). Read both copies. The test snapshot is `m.getFlag('sr2e','test')` (its `modifiers`, `dice`, `successes`, `targetNumber`, `label`); a contest is `m.getFlag('sr2e','contest')` (`sides[i].label`). Buttons used here: `defend`, `resist`, `karmaReroll`, `ramSelf` (rammer's damage), `applyDroneLink`, `applyLocks`, `resistSpell` (resist a power).
- **Dice:** `window.__zzRU ??= CONFIG.Dice.randomUniform;` then `CONFIG.Dice.randomUniform = () => 0.2` gives all 5s, `() => 0.99` all 1s and `() => 0.5` all 3s. Never use a value below 0.17 (sixes re-roll for ever). Dice are rolled in the tab that runs the call, so rig the tab that acts. Restore with `CONFIG.Dice.randomUniform = __zzRU`.
- **House rules (GM):** the same helpers as v0.72: `const HR = async (path, v) => { const c = game.settings.get('sr2e','houseRules'); const values = { ...c.values }; if (v === undefined) delete values[path]; else values[path] = v; await game.settings.set('sr2e','houseRules', { values, advanced: c.advanced ?? {} }); };` and `const HRA = async (path, v) => { const c = game.settings.get('sr2e','houseRules'); const advanced = { ...(c.advanced ?? {}) }; if (v === undefined) delete advanced[path]; else advanced[path] = v; await game.settings.set('sr2e','houseRules', { values: c.values ?? {}, advanced }); };`. Read back with `game.sr2e.api.rules.NETRIG_V73` (or `DRONES_V73`, `CHARACTERS_V73`, `CROSSCUT_V73`). `HR(path)` with no value puts the default back. An Advanced path must already exist in the shipped rules (`coerceRule`), so a whole object is replaced, never a new key added. **Put each switch back at the end of its check** unless the check says otherwise.
- **Edges and flaws** (section N) need `HR('STREET.qualities.enabled', true)`; put it back after section N.
- **Active GM:** sensor-lock lapses (section E), the morale "broken" clean-up (section Q), timed statuses, projects and training finishing on the clock (sections Q, R, S), and area sweeps (section O) run on the active GM's client. Check `game.users.activeGM?.name === 'GM AI'` at the start. If it isn't, mark those hook parts "not run".
- **World time:** save `window.__zzT = game.time.worldTime` once and put it back at clean-up. Big time steps here: up to 2 days (sections R and S).
- **Tokens:** the world is paused, so create tokens with `scene.createEmbeddedDocuments('Token', [(await a.getTokenDocument({x, y, actorLink: true})).toObject()])` (x, y = the top-left corner: centre − 50 for a 1 m token). NPCs get unlinked tokens where the check says so (no `actorLink`). To move a token, delete it and create it again.
- **Sheet actions:** `game.sr2e.runSheetAction(actor, action, dataset, event)` (actions used: `jackIn`, `systemTest`, `rollSkill`, `addSkill`, `negotiatePay`, `payLifestyle`, `droneLink`, `recordAsIs`; on a vehicle sheet `clearDroneLink`). Newest dialog: `const dlg = () => [...document.querySelectorAll('.application.dialog')].at(-1);`. Close any leftover `DialogV2` before a dialog-driven check.
- **Change target number (GM, section P):** the dialog is only on the chat card's right-click menu. Helper: `const tnMenu = async (m) => { const li = document.querySelector(`#chat-log [data-message-id="${m.id}"], .chat-log [data-message-id="${m.id}"]`); const r = li.getBoundingClientRect(); li.dispatchEvent(new MouseEvent('contextmenu', { bubbles: true, cancelable: true, clientX: r.x + 20, clientY: r.y + 20 })); await new Promise((s) => setTimeout(s, 300)); [...document.querySelectorAll('#context-menu li, .context-menu li')].find((e) => /Change target number/.test(e.textContent))?.click(); await new Promise((s) => setTimeout(s, 500)); return [...dlg().querySelectorAll('details > summary')].map((s) => s.textContent.trim()); };`. Rows inside a group: `[...dlg().querySelectorAll('details')].find(d => d.querySelector('summary').textContent.trim() === 'Hearing').querySelectorAll('label')`.
- **Advancement log (section R):** `await game.sr2e.api.flushAdvancement()` before reading `actor.getFlag('sr2e','advancement')` (oldest first; each line has `what`, `by`, `approvedBy`, `nuyen`, `karma`, and `refund` on refund lines).
- **Approval queue:** `game.settings.set('sr2e','approvalQueue', true)` (GM) only where a check says so; the GM approves in the GM panel (`game.sr2e.gmPanel()`) → Requests (`game.sr2e.api.pendingRequests()` lists them).
- **Undo log (section O):** `game.sr2e.undoLog.steps()[0]` is the newest step (`entries[]` with `op`, `docName`, `name`); `game.sr2e.undo()` undoes it. Wait 2 s between actions you want as separate steps (clicks within 1.5 s merge).
- **Two clients at once.** Both tabs stay open the whole run. These need both live at the same time: section C (the player rams, the GM defends, the player rolls the rammer's damage), section F (a player's intercept is applied by the GM's client by itself, `autoApplyGm`; a takeover waits for the GM's click), the approval-queue checks (36, 38, 61), and every "active GM" hook above.
