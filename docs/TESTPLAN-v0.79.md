# v0.79.0 live-test plan: the verified fixes from the owner's rules summaries (RULES.DOCS_V79)

**One tester, one built-in browser pane**, logged in as **GM AI** for everything except section K, where the same pane logs in as **ZZ Testplayer** and then goes back to GM AI. Drive everything with JavaScript and read documents and the DOM. After a click, an update or a new card, wait about 500 ms before reading (1 s for chat-card buttons). Every test document is named "ZZ …". Each check is **Setup → Action → *Expected***, with the old way (the house rule switched back) where it is cheap. "Record" means the code's behaviour is debatable or a likely gap: write down what happens and don't fail the check for it. Note console errors per section (`read_console_messages`, pattern `sr2e|Error|error`).

**Priority.** **[M]** = must-run (66 of the 72 checks). **[X]** = extra, run if time allows, in order.
